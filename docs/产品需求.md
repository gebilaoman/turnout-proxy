# 代理切换扩展：产品定位与功能清单

Sep 28, 2026 · @gebilaozhongyi

## 产品定位

**名称**：Turnout（道岔：一条入口，扳一下换轨）。商店标题为 `Turnout – Proxy Switcher`；图标和弹窗只用 Turnout。代码仓库：[gebilaoman/turnout-proxy](https://github.com/gebilaoman/turnout-proxy)。

**一句话**：给同时用多个代理客户端的个人用户，一个装上就能用、一键切换、状态一眼可见的 Chrome 代理切换器。

**目标用户**：在电脑上运行 FlClash、Clash Verge、v2rayN 或机场自带客户端的个人用户，尤其是同时有 2–3 个客户端、哪个稳定用哪个的人。

**非目标用户**：需要在浏览器里写复杂分流规则的重度用户（ZeroOmega 更合适）、企业团队、跨境多账号 IP 隔离。

| 维度 | ZeroOmega | FoxyProxy | 我们 |
| --- | --- | --- | --- |
| 上手方式 | 手动建情景模式 | 手动录入，选三种模式之一 | 自动发现本机客户端，起个名字即可 |
| 切换对象 | 情景模式 | 代理或模式 | 客户端 / 直连 / 跟随系统 |
| 状态可见 | 无在线状态 | 颜色标识 | 在线、延迟、出口 IP |
| 故障处理 | 静默失效 | 静默失效 | 自动切备用，并说明原因和修复步骤 |
| 分流规则 | 强 | 强 | 内置规则订阅，一份规则对所有客户端生效 |

## 产品原则

每条原则对应竞品差评里的一类高频问题，功能取舍有冲突时以此为准。

1. **规则在扩展里配一次，对所有客户端生效**：哪些网站走代理由扩展的规则订阅决定，客户端只负责提供出口；切换客户端时不用重新配置分流。客户端保持规则模式或全局模式均可，不会产生冲突。
2. **状态永远可见**：任何时候都能看到当前走哪个客户端、是否在线、出口 IP 是什么。
3. **坏了要说清楚**：不允许静默失效或静默直连；每种故障都有原因和修复步骤，规则订阅失败也要提示。
4. **配置永不丢失**：本地持久保存，升级前自动备份，随时可导出；改版保留旧操作路径。
5. **可信赖**：开源并对应商店版本、权限最小、无遥测、无推销、免注册，品牌名不蹭 SwitchyOmega。

## 首版功能（P0）

首版共 12 项，围绕"发现 → 切换 → 智能分流 → 看状态 → 出问题有兜底"一条主线；按网站手动指定放第二版。

| 功能 | 说明 | 对应痛点 |
| --- | --- | --- |
| 自动发现客户端 | 扫描常见本地端口（7890、7897、10808、10809、1080、8888 等），识别 HTTP / SOCKS 类型，列出供用户命名 | 手动录入麻烦；把 HTTP 请求发到 SOCKS 端口 |
| 客户端列表 | 名称 + 地址 + 端口 + 类型，可手动增删改 | 多客户端需求 |
| 弹窗一键切换 | 两个选择：模式（智能分流 / 全部走代理 / 直连）+ 出口（各客户端 / 跟随系统）；当前项高亮 | 模式概念复杂 |
| 规则订阅（智能分流） | 内置一份默认规则，开箱即用；可换成自定义订阅地址；每天自动更新，失败时沿用上次成功版本并提示原因；扩展内打包一份兜底规则，首次离线也能用 | 客户端分流不会配；换客户端要重配；订阅下载失败无提示 |
| 在线状态与延迟 | 弹窗打开时实时测；后台每分钟检测一次 | 不生效难排查 |
| 出口 IP 与地区 | 显示当前实际出口 IP 和所在地区 | 切换后仍是原 IP、不确定是否生效 |
| 自动切备用 | 可设一个备用客户端，当前连不上时浏览器自动改走备用；是否允许最终回落直连由用户决定，默认不允许 | 客户端掉线全站打不开；静默直连泄露 |
| 图标状态 | 图标颜色 / 角标显示当前客户端、当前模式和异常 | 不知道现在走的是哪 |
| 环境与冲突检测 | 识别其他扩展接管代理、企业策略锁定、Chrome 拦截 127.0.0.1（LNA），点名原因并给出修复步骤 | 多扩展抢控制权；Chrome 升级后失效 |
| 配置持久与备份 | 记住当前选择；升级前自动备份；一键导出 / 导入 | 升级丢配置；重启后记不住 |
| 从 ZeroOmega / SwitchyOmega 导入 | 读取其备份文件中的代理服务器和规则订阅地址 | 迁移成本 |
| 首次引导 | 未检测到客户端时说明原因并引导手动添加；端口冲突时提示修改 | 新手上手；也满足商店审核复现 |

## 第二版功能（P1）

首版上线并收到反馈后再做，优先做"按网站指定出口"。

| 功能 | 说明 | 为什么放第二版 |
| --- | --- | --- |
| 按网站指定出口 | 弹窗中一键把当前网站设为直连或某个客户端，规则默认持久保存 | 核心场景不依赖它，先验证需求强度 |
| 当前页面失败请求 | 列出本页加载失败的域名，一键加入规则 | 依赖上一项 |
| 多设备同步 | 用浏览器账号同步客户端列表和规则，冲突时不静默覆盖 | 不同电脑端口可能不同，需设计同步范围 |
| Firefox / Edge 版 | Edge 直接复用；Firefox 用 `proxy.onRequest` 重写路由层 | 先用 Chrome 验证 |
| Clash API 增强 | 用户填入控制器地址和密钥后，读取真实端口、TUN 状态、节点延迟 | 各客户端默认关闭或差异大 |
| 快捷键切换 | 键盘快捷键在客户端之间轮换 | 低成本加分项 |
| 无痕窗口独立出口 | 无痕窗口可指定不同的客户端 | 需求频率待验证 |

## 明确不做

以下功能即使有用户要求也不做，除非定位改变。

| 不做的功能 | 原因 |
| --- | --- |
| 情景模式 / 自动切换模式嵌套 | SwitchyOmega、FoxyProxy 概念复杂的根源 |
| 多条订阅叠加、规则优先级编排 | 规则订阅只保留"一条订阅 + 少量手动例外"，避免重回复杂 |
| 自带代理节点、推销代理服务 | 损害信任，FoxyProxy 因此被差评 |
| 账号注册、自建云端 | 增加门槛和隐私疑虑 |
| 遥测与使用统计 | 与"可信赖"原则冲突 |
| 按标签页代理、多账号 IP 隔离 | 小众场景，防关联浏览器更合适 |
| SOCKS5 账号密码认证 | Chrome 本身不支持；本地客户端一般无需认证 |
| PAC 脚本编辑、远程 PAC | 复杂度高，远程脚本还有商店审核风险 |

## 成功指标与待决问题

**成功指标（首版）**

- 装上后 1 分钟内完成首次切换，客户端被自动发现的情况下无需手动输入。
- 升级导致配置丢失的事件为 0。
- 商店评分保持在 4.5 以上（ZeroOmega 为 4.7，FoxyProxy 为 3.8）。
- 差评中"不生效不知道为什么"一类占比明显低于竞品。

**待决问题**

- [ ] 产品名称：已定 Turnout，仓库已定 gebilaoman/turnout-proxy；待核对 Chrome/Edge 商店重名与域名
- [ ] 万达云客户端的默认端口和协议，加入自动发现列表
- [ ] 在当前稳定版 Chrome 实测 127.0.0.1 是否被 LNA 拦截
- [ ] 默认规则源：用"需要代理的网站列表"（如 GFWList）还是"国内直连列表"；后者更全但体积大，需实测 PAC 性能
- [ ] 出口 IP 查询用哪个服务（需对外请求，影响"不联网"承诺的表述）
- [ ] 开源许可证（ZeroOmega、SmartProxy 均为 GPL-3.0）
- [ ] 首版是否同时上架 Edge
